## Incremento

**Vertical Slice 4B — Enterprise Vault Export Orchestration (primeiro incremento funcional)**

Base obrigatória: `main` após o merge do PR #29 (`57e3f5f57c87d61bb9b63d77b2f953b61f98fc4e`).

- `docs/ev/capability-discovery.md`;

## Objetivo

Introduzir o primeiro caminho real e governado para **solicitar e executar exportação Enterprise Vault para PST segmentado**, selecionando adapter exclusivamente a partir de uma descoberta de capacidades previamente concluída e utilizável.

O Slice 4B NÃO autoriza suporte comercial genérico a versões de EV ainda não certificadas. Quando a família/build não tiver adapter certificado, o sistema deve permanecer em modo assistido ou bloqueado, conforme ADR-0013.

## Escopo funcional mínimo

1. **Comando durável de exportação**
   - modelar solicitação de exportação vinculada a tenant/projeto, ambiente EV, archive lógico, discovery/version snapshot e adapter selecionado;
   - enfileirar por infraestrutura de Jobs já existente;
   - idempotência determinística por escopo + archive + snapshot de discovery + política/target de segmentação;
   - nenhuma execução direta na thread HTTP/Portal.

2. **Preconditions fail-closed**
   - discovery obrigatória e madura;
   - resultado precisa permitir exportação;
   - adapter/build deve estar certificado no catálogo/matriz vigente;
   - `LaboratoryValidated` não pode ser elevado por código deste slice;
   - intervalo real `DetectedMinPstSizeMb`/`DetectedMaxPstSizeMb` deve ter sido comprovado quando segmentação automática for requerida;
   - alvo operacional default do produto: `18432 MB`, aceito apenas se estiver dentro do intervalo detectado e abaixo do hard policy M365 de 20 GB; se não estiver, bloquear/assistir — não inventar capacidade.

3. **Contrato de adapter**
   - reutilizar/implementar `IEvExportAdapter` de forma compatível com os documentos existentes;
   - seleção por capabilities, nunca apenas por string de versão;
   - adapter nativo PowerShell somente para build/família efetivamente certificada;
   - nenhuma string PowerShell arbitrária vinda do Control Plane;
   - comandos/scripts permitidos devem ser versionados, allowlisted e tratados como artefatos do produto.

4. **Worker EV isolado**
   - execução fora do Control Plane;
   - identidade de serviço de menor privilégio;
   - sem Domain Admin;
   - sem inbound requirement novo;
   - registrar progresso, retry e cancelamento segundo o contrato de adapter;
   - perda de lease/fencing deve impedir novos efeitos e impedir conclusão indevida.

5. **Custódia e artefatos**
   - registrar os PSTs exportados como artefatos imutáveis/metadados de origem;
   - SHA-256 dos bytes exatos após fechamento de cada PST;
   - não registrar conteúdo de mensagem, assunto, anexos, UPN/SMTP em claro ou caminhos sensíveis em logs;
   - manter lineage do archive EV/discovery/export request até cada PST gerado;
   - não alterar bytes após hash; qualquer transformação futura é outro estágio.

6. **Retry / crash recovery**
   - retry deve ser idempotente e não duplicar uma exportação já confirmada;
   - estado ambíguo após possível efeito externo/local deve ir para reconciliação/recuperação, não repetir cegamente;
   - cancelamento e retry seguem o `EvExportReport`/contrato documentado;
   - conjunto de saída aprovado deve ser único para a mesma operação lógica.

7. **Portal mínimo do Slice 4B**
   - a tela Enterprise Vault pode expor ação de exportação somente para papel autorizado e quando todos os gates estiverem satisfeitos;
   - o Portal apenas solicita/enfileira;
   - Presentation Mode continua estritamente read-only e deve recusar POST antes de tocar stores/jobs;
   - usuário sem autorização não pode inferir feature gate/certificação pela diferença de resposta;
   - usar PRG após POST aceito/replay para detalhes do Job.

## Fora de escopo — obrigatório

- nenhuma inspeção/split adicional via Aspose/libpff;
- nenhuma automação Outlook/COM como engine do produto;
- nenhuma ingestão de PST avulso gigante;
- nenhum AzCopy;
- nenhum Azure staging;
- nenhuma chamada Purview/Microsoft Graph/Exchange Online;
- nenhuma criação/início de import job Microsoft 365;
- nenhuma reconciliação M365;
- nenhuma alegação de suporte a EV não certificado;
- nenhuma elevação de `LaboratoryValidated` para `true`;
- não iniciar o próximo incremento de Purview/Upload/Reconciliation neste PR.

## Persistência / migrations

- migrations anteriores são imutáveis;
- novas migrations só se necessárias para o modelo durável de exportação, devem ser aditivas, determinísticas, RLS/tenant-project scoped e com grants mínimos;
- nenhuma alteração destrutiva ou backfill irreversível neste incremento;
- identities de manutenção não recebem acesso amplo a artefatos ou dados de exportação.

## Segurança obrigatória

- RBAC server-side; UI escondida nunca é controle de segurança;
- anti-IDOR: IDs de outro tenant/projeto devem ser externamente indistinguíveis de inexistentes;
- antiforgery para POST baseado em cookie;
- payload/input bounded;
- path traversal proibido; caminhos físicos são resolvidos server-side;
- arquivos gerados ficam em raiz controlada, com contenção de path e defesa contra reparse/symlink conforme baseline Windows;
- logs sanitizados e sem command line completa se contiver dado sensível;
- PowerShell somente através do adapter/worker previsto no ADR, sem comando livre do usuário;
- scripts/adapters devem respeitar assinatura/allowlist conforme estado de certificação documentado.

## Testes mínimos de aceite

Cobrir explicitamente, além da suíte existente:

1. discovery inexistente/cross-tenant/cross-project => nenhuma exportação;
2. discovery não madura/Blocked/Unsupported => nenhuma exportação;
3. ambiente sem adapter certificado => modo assistido/bloqueado, nunca execução silenciosa;
4. alvo `18432 MB` fora do intervalo detectado => bloqueio;
5. escolha do adapter por capability e não por versão textual;
6. mesma idempotency key + mesma operação => replay do mesmo Job/operação;
7. mesma key + operação divergente => conflito determinístico;
8. concorrência da mesma operação => exatamente um efeito lógico;
9. perda de lease/fencing => não concluir como sucesso e não iniciar efeito novo;
10. Presentation Mode POST => 403 e zero writes/zero job;
11. Viewer/Auditor/Approver sem papel operacional => 403 e sem revelar gate/certificação;
12. antiforgery inválido => rejeitado antes do use case;
13. path traversal/reparse => rejeitado;
14. hash de PST calculado sobre bytes exatos e metadado persistido;
15. logs/issues/errors sem PII/conteúdo e sem comando arbitrário;
16. migrations antigas byte-for-byte; eventual migration nova é aditiva;
17. suíte completa verde (`restore --locked-mode`, build Release, tests, format, secret scan/SCA existentes).

## Critério de conclusão

O incremento só pode receber `ARCHIVEBRIDGE_MERGE_APPROVED` quando:

- o caminho de exportação real estiver restrito a adapters/capabilities certificados e fail-closed;
- CI do HEAD exato estiver totalmente verde;
- não houver review thread/blocker aberto;
- nenhuma capacidade futura (AzCopy/Purview/import/reconciliation) tiver sido iniciada;
- documentação/threat model/dados de custódia refletirem exatamente o comportamento implementado.
