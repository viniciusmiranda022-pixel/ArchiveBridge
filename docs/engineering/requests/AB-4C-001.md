# ARCHIVEBRIDGE_ENGINEERING_REQUEST

REQUEST_ID: AB-4C-001

## Slice 4C — Passo 1: Enterprise Vault Connector Enrollment & Inventory Foundation

## Objetivo

Iniciar o incremento documentado **I4 / EPIC-05 — Enterprise Vault** após a conclusão do I3/Partition, criando a fundação segura do Source Connector para **enrollment outbound, capability discovery, inventário auditável e contratos de export**, sem executar exportação real de dados neste Passo.

Este Passo estabelece a fronteira de confiança entre Control Plane e host Enterprise Vault. O conector deve operar próximo ao dado, iniciar somente conexões outbound, possuir identidade própria, executar apenas ações allowlisted e publicar apenas metadados/resultados sanitizados. O Control Plane não recebe SMB nem credenciais do EV.

## Fontes de autoridade

- `docs/runbook/03-parte-iii-conectores-e-engine-pst.md`, especialmente §§15 e 16;
- `docs/runbook/06-parte-vi-plano-desenvolvimento.md`, I4 / EPIC-05;
- ADRs aceitos, threat model, governança e invariantes de tenancy/custody já mergeados;
- PRs #34, #35 e #36 para padrões de idempotência, evidência, fail-closed e versionamento.

Quando houver conflito, ADR aceito e decisão mais recente versionada no repositório prevalecem sobre exemplos antigos do runbook.

## Escopo obrigatório

1. Definir contratos Domain/Application para `SourceConnector`, enrollment, capability discovery, EV inventory snapshot e export request **sem** dependência concreta do snap-in/SDK EV em Domain/Application.
2. Modelar enrollment token one-time com expiração máxima de 15 minutos, consumo único e revogação explícita. Persistência deve ser tenant/project scoped, aditiva e determinística.
3. Modelar identidade durável do connector com `connector_id` opaco, thumbprint/public-key identity, hostname sanitizado, site, versão e capability set. Nunca persistir private key.
4. Implementar protocolo server-side de enrollment/registration preparado para mTLS/workload identity, com fail-closed se token expirado, reutilizado, revogado, tenant/project divergente ou identity binding inconsistente.
5. Implementar capability registry/version handshake: EV version, connector version, PowerShell snap-in registration/availability, export capability, inventory capability e support-matrix result. Schema desconhecido/incompatível deve bloquear export capability sem improviso.
6. Implementar inventário **read-only** normalizado a partir de um adapter substituível. O adapter concreto deste Passo pode ser test/deterministic fixture ou host abstraction; nenhuma execução real de `Get-EVArchive` é obrigatória neste PR se isso exigir credencial/host EV inexistente.
7. Inventário deve normalizar apenas metadados necessários: archive opaque identity/external stable id, archive type, vault-store identity/name quando permitido, status e capability diagnostics. Não trazer conteúdo de item, subject/body, attachment, credentials ou transcripts brutos para o domínio.
8. Persistir inventory snapshot e evidence hash de forma idempotente, append-oriented e tenant/project/connector scoped. Repetição do mesmo snapshot deve convergir; mudança real deve gerar nova versão/snapshot.
9. Definir contrato de `ExportRequest` e política (`MaxThreads`, `MaxPstSizeMb`, output capability, retry semantics) conforme o runbook, porém **não disparar `Export-EVArchive` real neste Passo**.
10. Defaults/limits documentados: `MaxPstSizeMb=18432`; aceitar somente intervalo documentado pelo cmdlet (500–51200 MB); `MaxThreads` dentro do envelope aprovado e sujeito a policy/capability.
11. Modelar diagnóstico para oversized native items e delta strategy como capabilities/unsupported states; não omitir a necessidade de tratar itens >250 MB / >2 GB, mas não implementar export real deles neste Passo.
12. Aplicar outbound-only trust model: nenhum endpoint ou contrato deve exigir inbound network access do Control Plane ao host EV; nenhum SMB share/credential do EV pode cruzar para o Control Plane.
13. Adicionar audit/custody events para enrollment, registration, capability discovery e inventory snapshot sem PII/segredo indevido.
14. Aplicar anti-IDOR e tenant/project isolation em todos os stores/use-cases/read models novos.
15. Atualizar threat-model delta, runbook operacional do connector, data classification e support-matrix placeholder/versioning rules.
16. Adicionar testes unitários, arquitetura e integração cobrindo os critérios abaixo e executar todos os gates do repositório.

## Acceptance criteria mínimos

1. Enrollment token é one-time, expira em <=15 min e não pode ser reutilizado.
2. Connector identity fica vinculada a tenant/project e material público; private key/credential nunca é persistida pelo Control Plane.
3. Enrollment/registration inválido, replay, tenant mismatch ou identity mismatch falha fechado.
4. Capability discovery incompatível impede capability de export e produz diagnóstico estruturado/auditável.
5. Inventory adapter permanece atrás de interface; Domain/Application não referenciam tipos PowerShell/EV/vendor.
6. Snapshot de inventário é determinístico, hashado, scoped e versionado; replay idêntico não duplica efeito lógico.
7. Mudança real de inventário gera novo snapshot/versão sem reescrever evidência anterior.
8. Nenhum path absoluto, credential, token, private key, transcript bruto, subject/body/attachment ou item content entra em logs/evidence.
9. O desenho continua estritamente outbound-only; nenhum SMB/inbound Control Plane -> EV é introduzido.
10. ExportRequest/Policy valida `MaxPstSizeMb` e `MaxThreads` conforme limites aceitos, mas nenhum export real ocorre neste Passo.
11. Cross-tenant/cross-project/forged connector ID são negados sem revelar existência.
12. Migrations anteriores permanecem byte-for-byte; novas migrations passam hash/determinism e least-privilege grants.
13. CI completo verde no HEAD final.

## Testes obrigatórios

- token expirado, reutilizado, revogado e tenant mismatch;
- identity binding/thumbprint mismatch;
- registration idempotente do mesmo connector;
- capability handshake suportado e incompatível;
- inventory snapshot determinístico + hash;
- replay do mesmo inventário sem duplicidade lógica;
- inventory changed => nova versão;
- schema/field capability desconhecida => export capability blocked;
- forged connector/cross-tenant/cross-project anti-IDOR;
- policy boundaries de `MaxPstSizeMb` e `MaxThreads`;
- secret/PII redaction em audit/evidence/logging;
- architecture tests provando ausência de dependência EV/PowerShell em Domain/Application;
- migration hashes anteriores estáveis.

## STOP-THE-LINE / fora do escopo

Este PR NÃO autoriza:

- execução real de `Export-EVArchive`;
- disparo real de `Get-EVArchive` contra ambiente de cliente se não houver fixture/host autorizado;
- armazenamento de credenciais EV no Control Plane;
- inbound SMB/RPC/WinRM do Control Plane para host EV;
- Outlook/COM automation;
- export NATIVE/EML real;
- split/repair adicional de PST;
- AzCopy/Azure staging/SAS;
- Purview, Graph, Exchange Online ou import job;
- delta/freeze operacional real em ambiente EV;
- descomissionamento de EV.
